# NEXIA plain-language interface standard

Owner-approved 2026-11-25. Apply to new and revised user-facing screens, help text, errors, task status and approval dialogs.

- Keep branded names, but always explain their everyday purpose: Command (assign work), Workspace (talk to AI), Orchestrator (track work), Cortex (what AI remembers), Forge (connect apps), Sentinel (AI safety), Pulse (how work is going), Vault (protect information), Constitution (AI rules).
- Show ordinary-language choices before technical settings. A question that only creates a recorded inquiry must not be described as live chat or authorization to work. A saved task is not a started task; a reported assignment is not proof of an active AI.
- Explain what happened, what it means and what the user can do next. Put necessary technical evidence behind an Advanced details disclosure where practical; do not hide safety warnings, spending, data sharing, permission boundaries or uncertainty.
- Use direct action labels and explain consequences before approval. Keep approval bound to the exact action; do not infer authorization from discussion or simplify away safeguards.
- Label unfinished features as not ready. AEGIS (pause AI work) and BLACKOUT (emergency shutdown) are design intentions until independently verified; existing Stop Everything does not guarantee cancellation of in-flight external actions.
- Avoid unsupported pricing promises. Cost depends on the actual request and AI used.
- Make captions, focus states and touch targets usable on mobile. Validate at phone and desktop widths with synthetic fixtures, and include independent review before release.

Acceptance question: could a first-time user without engineering or AI knowledge tell what each option does, what will happen, what is not confirmed, and how to proceed?

This standard changes presentation, not runtime authority, provider access, budgets or release gates.
