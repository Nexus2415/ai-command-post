# ARN-169: Brain private document deliverables

Source-only first milestone. The existing ChatGPT worker tool dispatch can create a real deterministic DOCX via an explicitly injected synthetic capability. It accepts only structured title/headings/paragraphs, a simple .docx filename, and bounded content. No macros, external links, filesystem destination, model-visible file bytes or new dependency. Missing scope or dry-run refuses. The fixture writes a private file to an isolated temporary directory and independently opens the actual ZIP and XML with Python 3; it tests exact replay, altered content, cross-principal, expiry, stop and private-thread revocation. Python 3 is required for the independent document-format test (available on the existing Ubuntu CI runner).

The fixture is not production authority or durable workspace storage. Next: actual scoped owner-private artifact storage and retrieval with atomic stop/expiry/fence/lineage enforcement, and a full scripted goal through document creation and independent verification. No runtime adapter, provider request, new permissions, or production schema change. PDF, spreadsheets and slides remain unsupported. Do not claim full ARN-169 readiness until these requirements and independent review are satisfied.

The actual scripted planner/worker test now creates and retrieves the DOCX through `document.create`, independently parses it, verifies the recorded digest and reconciles the goal at $0 with fake model replies. A model's unsupported claim of completion is blocked if the explicitly bound document capability has no current readback-confirmed receipt. Production private storage and actual fenced authorization remain unimplemented.

Candidate `db/document-artifacts.sql` and `src/document-storage.ts` add actual durable private storage via an injected RPC adapter. The disposable PG test creates an actual DOCX, verifies exact replay, restarts PostgreSQL, reads back and independently parses the bytes, rejects stale run and wrong principal, and tests stop, redaction and thread deletion. The candidate functions grant no caller role. SQL trusts the already-authorized adapter's grant; a current ACP claim is necessary for write but is not an owner grant or canonical broker attempt. The actual deployed authenticated grant/role mapping and owner UI retrieval still require separate qualification. No migration is applied.

## Owner access candidate
The unregistered owner download handler derives the pseudonymous principal from the existing named-owner signed session (not a password header, browser parameter or model output), checks same origin, validates the exact project/thread/artifact receipt and bytes, and returns only verified DOCX with no-store/attachment headers. The separate read-only `ws_document_owner_get` candidate keeps the owner's document readable after the worker's grant expires, subject to private scope, stop and revocation; no caller EXECUTE grants. This is not a live route, and changing owner credential/retention or role policy needs separate review. Candidate only; no production deployment or new access rights.
