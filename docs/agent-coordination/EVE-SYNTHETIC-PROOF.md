4. **Cost gate:** independently verify the provider and models allow the positive run at incremental **$0**, with a worst-case reservation and durable accounting. **A second disabled-session probe is separately authorized only if its potential execution is also included in an explicit owner approval and a worst-case cost envelope for BOTH operations.** A budget of 0 by itself is not proof of free execution. 5. **Dispatch gate:** ACP `api/eve.js` currently returns **unsupported** for commands; `api/eve-oidc.js` is an inert request builder. Do not bypass either by calling an undocumented endpoint. Confirm from installed Eve source a real session entrypoint, response schema, OIDC subject/trust, deployment protection trust, single-owner admission and idempotent attempt/lease. Missing any one is **BLOCKED**, not a reason to bypass the adapter.

## Abort and rollback criteria

Stop immediately on ambiguous 200/202, missing authenticated identity, unknown route/schema, wrong tenant, duplicate execution, unbounded retry, cost > $0, credentials exposed, production-side effects, protection bypass, or failure to observe exact flag state. Disable the preview flag and record the discrepancy as **BLOCKED**. On network timeout or ambiguous response, the operation is **terminally BLOCKED for this exercise**. Do **not** replay or reissue it while the result is unknown, even after an inconclusive or delayed status lookup; reconcile `operationId` with authoritative durable evidence and obtain a new scoped approval before any different attempt. The original attempt is never auto-retried in this proof. If the kill-switch test creates any run after disable, open an incident issue and do not declare this criterion passed.

The ACP GitHub Actions engine has a **different** kill switch, `ACP_ACTIVE`, and defaults to off with `ACP_DRY_RUN=true`; this runbook neither enables that engine nor uses consumer AI sessions as authenticated model execution. `ACP_EVE_ACTIVE`, production `ARNEXYIA_MULTI_AI_ACTIVE`, Gemini suspension, client authorization, and `limited_live_ready=false` stay unchanged unless separately approved.
